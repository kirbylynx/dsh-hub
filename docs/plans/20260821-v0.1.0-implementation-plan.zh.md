# dsh-hub v0.1.0 实施计划

语言：[English](20260821-v0.1.0-implementation-plan.md) | 简体中文

本文记录公开的 v0.1.0 MVP 实施基线和后续计划，不包含私有运维细节。

## 1. 已完成 MVP 切片

| 切片 | 领域 | 公开完成证据 |
| --- | --- | --- |
| M1A | 安全和凭据生命周期 | registry key、token、replacement grant、ACL、CSRF、Origin 和审计行为的 unit/security tests |
| M1B | 有界 relay 协议 | HTTP、WebSocket、cancel、credit、heartbeat 和 backpressure 的 protocol/tunnel tests |
| M1C | 真实 DSH 兼容基线 | 核心 HTTP/WS seam 的本地真实 DSH 检查 |
| M2 | 部署模板 | local 和 existing-Caddy 模板的 Compose/Caddy/Authelia 检查 |
| M3A | 诊断 | owner-only diagnostics API 和 Portal action |
| M3B | 运维基线 | metrics、alert rule checks、recovery rehearsal、logging and redaction checks |
| M4 | Plugin-first 集成 | plugin install/join/runtime/status/diagnostics/remote capability tests |

## 2. 验证命令

```bash
npm test
npm run deploy:m2:check
npm run deploy:m2:check:deep
npm run deploy:m2:existing-caddy:check
npm run deploy:m2:existing-caddy:check:deep
npm run deploy:m3:alerts:check
npm run deploy:m3:recovery:check
npm run deploy:m3:logging:check
```

部分深度部署检查需要 Docker。

## 3. 公开发布规则

- 不提交真实 `.env` 文件。
- 不提交真实 Authelia 用户数据库。
- 不提交真实 secret 文件、SQLite 数据库、备份、日志或本地 DSH 凭据。
- 公开文档和测试使用 `hub.example.com` 与保留 IP。
- 真实部署 runbook 放在私有运维 overlay 仓库。
- 模板检查通过只是模板证据，不是生产证明。

## 4. Post-MVP 实施顺序

公开路线图维护在 `docs/ROADMAP.md`。

推荐顺序：

1. 会话历史懒加载和大会话性能。
2. 生产发布加固。
3. 多用户角色和权限。
4. 管理后台。
5. DSH 版本兼容矩阵。
6. 托管 DSH 容器评估。
7. 在权限和管理员操作定义完成后，再做托管 DSH 实例池自动分配。

## 5. Review checklist

合并公开变更前：

1. 检查变更文件并运行 `git diff --check`。
2. 按风险比例运行测试。
3. 扫描变更文档中的真实域名、IP、本地路径、凭据和私有项目名。
4. 行为变化时更新 README、protocol docs、roadmap、release notes 和 operations docs。
5. 保持协议变更与 fixtures/tests 同步。
