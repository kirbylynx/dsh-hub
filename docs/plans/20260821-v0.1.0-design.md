# dsh-hub v0.1.0 design

Language: English | [简体中文](20260821-v0.1.0-design.zh.md)

This document describes the public v0.1.0 MVP design baseline without private
deployment evidence.

## 1. Architecture

```text
Browser
  │
  │ HTTPS / WSS
  ▼
Caddy + Authelia
  │
  ▼
dsh-hub-service
  │
  │ outbound tunnel sessions
  ▼
dsh-hub-plugin or dsh-hub-client
  │
  ▼
local DSH loopback web server
```

The center owns authentication, authorization, registration, audit, and relay
limits. Instance-side code owns local DSH probing, credential storage, and the
outbound tunnel connection.

## 2. Domain model

- Portal host: `https://hub.example.com`.
- Control host: `https://control.hub.example.com`.
- Auth host: `https://auth.hub.example.com`.
- Instance hosts: `https://<instanceId>.instances.hub.example.com/`.

Instance subdomains are a design requirement because DSH Web resolves API calls
from the current page origin.

## 3. Data model

The service persists:

- namespaces;
- registry keys as digests, prefixes, and the current revealable namespace join
  credential when available;
- instances;
- instance tokens as digests and prefixes;
- replacement grants as digests and consumption state;
- idempotency records;
- audit events;
- health observations.

The database may persist the current revealable plaintext registry key for
authorized namespace-manager reveal/copy flows. Plaintext replacement grants and
instance tokens must never be persisted after issuance, and registry keys must
never enter logs, audit details, URLs, or tunnel frames.

## 4. Security model

- Only trusted proxies may provide identity headers.
- External identity headers are scrubbed before authentication/forwarding.
- Portal writes require Origin + CSRF + strict schema validation.
- Instance relay requires both center authentication/ACL and a live authorized
  tunnel.
- DSH receives sanitized loopback-style requests; therefore the hub is the
  effective security boundary.
- Metrics are internal-only and must avoid namespace/instance labels or secrets.

## 5. Registry key and instance token semantics

- A namespace has one active registry key at a time.
- A registry key can register multiple fresh installations.
- Rotating the registry key changes only future registration.
- Existing instance tokens remain valid until expiration, rotation, leave, or
  revoke.
- Revoked instances must not automatically re-register with only a registry key.
- Recovery uses a short-lived owner-approved replacement grant.

## 6. Relay design

The relay uses protocol v1.1:

- hello and capability negotiation;
- HTTP request/response frames;
- WebSocket open/data/close frames;
- cancel frames;
- credit frames for flow control;
- heartbeat and health frames.

Both service and client/plugin enforce size, timeout, and backpressure limits.

## 7. Plugin-first DSH integration

The plugin path provides:

- host-side DSH bundle;
- tunnel adapter using the shared client tunnel runner;
- credential store;
- status view;
- diagnostics summary;
- browser settings card;
- same-origin status endpoint;
- explicit remote capabilities overlay;
- `dsh-hub-web` launch helper;
- `plugin-install` and `plugin-join` CLI helpers.

The standalone agent path remains useful for diagnostics, bootstrap, and
fallback deployments.

## 8. Deployment design

Public deployment examples are templates:

- `deploy/m2-local`: all-in-one local Compose with Caddy and Authelia.
- `deploy/m2-existing-caddy`: backend Compose services for hosts where a system
  Caddy already owns public ports.
- `deploy/m3-observability`: metrics and alert rule validation.
- `deploy/m3-recovery`: local backup/restore rehearsal.
- `deploy/m3-logging`: log retention and redaction checks.

Private production overlays should live outside the public repository.

## 9. Compatibility notes

dsh-hub tracks specific DSH seams: profile composition, plugin loading, browser
client registration, web server routing, directory picker behavior, and DSH HTTP
/ WebSocket APIs. DSH is still evolving, so upgrades should go through an
isolated compatibility matrix before becoming the default baseline.
