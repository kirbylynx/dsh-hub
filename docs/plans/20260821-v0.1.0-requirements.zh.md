# dsh-hub v0.1.0 需求

语言：[English](20260821-v0.1.0-requirements.md) | 简体中文

本文描述公开的 v0.1.0 MVP 需求基线，不包含真实部署证据或本地环境细节。

## 1. 产品目标

dsh-hub 为通常只监听 loopback 的 DeepSeek Harness（DSH）实例提供远程访问/控制中心。
用户在 hub 完成认证后，选择有权限的 namespace 和 instance，并通过安全出站 tunnel 打开
原始 DSH Web UI。

## 2. 核心术语

| 术语 | 含义 |
| --- | --- |
| namespace | v0.1.0 中由一个用户拥有的租户或逻辑分组 |
| registry key | 用于新实例注册的 namespace 级 key |
| instance | 一个已注册的 DSH endpoint |
| instance token | tunnel client 使用的长期实例凭据 |
| replacement grant | owner 批准的短期一次性恢复凭据 |
| delivery | 实例侧模式：`plugin` 或 `agent` |

## 3. MVP 需求

### 3.1 中心和 Portal

- 中心服务必须暴露 namespace、instance、registration、tunnel、health、metrics 和 portal endpoint。
- Portal 写操作必须要求已认证用户身份、精确 Origin 校验、CSRF、严格 request schema，以及签发 secret 时的 idempotency key。
- Portal 读操作必须执行 ACL 检查并返回最小字段。
- Portal 不得暴露 registry key digest、replacement grant、instance token digest、pepper key ID、installation ID 或内部数据库 ID。

### 3.2 Namespace 和 registry key

- v0.1.0 使用单 owner namespace 模型。
- 每个 namespace 同一时间只有一个 active registry key。
- 当前 registry key 可以注册多个新 installation。
- 轮换 registry key 只会让旧 key 不能再用于后续注册。
- 轮换 registry key 不得 revoke、rotate、断开或以其它方式影响已签发的 instance token。

### 3.3 实例注册和生命周期

- 新实例使用 namespace registry key 注册。
- 已绑定过的 installation 不得只用 registry key 静默重新注册；恢复需要 replacement grant。
- instance token 可由实例轮换。
- 实例可 self-leave，并在确认 revoke 后清理本地凭据。
- Owner 可 revoke 实例；revoke 会终止 active token 和 tunnel。

### 3.4 Tunnel 和 relay

- tunnel 协议必须支持 HTTP、WebSocket、取消、流控、heartbeat、health report 和有界资源使用。
- relay 转发到 DSH 前必须剥离中心凭据和身份头。
- 响应必须剥离 hop-by-hop header 和中心内部 header。
- 大流或慢流必须受配置限制和 backpressure 约束。

### 3.5 DSH 集成

- v0.1.0 推荐路径是 plugin-first。
- 独立 client 保留为 fallback 和诊断工具。
- DSH Web UI 应作为整页实例子域打开。
- iframe embedding 保持实验状态。
- 可用时，远程目录选择应使用面向浏览器的 picker overlay，而不是实例机器的 native picker。
- 远程 `openPath` 在安全替代方案存在前应禁用或 gate。

### 3.6 部署与运维

- 公开示例必须支持：
  - 本地 all-in-one Docker Compose；
  - 既有系统 Caddy 后面的后端服务；
  - 基于 Authelia 的认证；
  - 仅用于示例的 secret 文件；
  - metrics 和告警规则检查；
  - 本地备份/恢复演练；
  - 日志保留和脱敏检查。
- 真实 secret、真实 hostname、真实 IP 和真实运维记录不得提交到公开仓库。

## 4. v0.1.0 非目标

- 多用户角色、共享 namespace 和成员管理。
- 管理后台。
- 会话历史懒加载。
- 托管 DSH 容器池。
- 无头自动化 API。
- P2P 或高可用。
- 强敌对租户 SaaS 隔离。
- 远程 `openPath` 替代 UI。

## 5. 验收标准

- `npm test` 通过。
- 协议 fixture 与 `docs/protocol.md` 一致。
- local 和 existing-Caddy 示例的部署模板检查通过。
- 公开文档只包含通用 example domain 和 path。
- secret 示例明确标注为不安全占位符。
