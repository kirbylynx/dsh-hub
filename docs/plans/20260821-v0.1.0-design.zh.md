# dsh-hub v0.1.0 设计

语言：[English](20260821-v0.1.0-design.md) | 简体中文

本文描述公开的 v0.1.0 MVP 设计基线，不包含真实部署证据。

## 1. 架构

```text
Browser
  │
  │ HTTPS / WSS
  ▼
Caddy + Authelia
  │
  ▼
dsh-hub-service
  │
  │ outbound tunnel sessions
  ▼
dsh-hub-plugin or dsh-hub-client
  │
  ▼
local DSH loopback web server
```

中心负责认证、授权、注册、审计和 relay limit。实例侧代码负责本地 DSH 探测、凭据存储和出站 tunnel 连接。

## 2. 域名模型

- Portal host：`https://hub.example.com`。
- Control host：`https://control.hub.example.com`。
- Auth host：`https://auth.hub.example.com`。
- Instance hosts：`https://<instanceId>.instances.hub.example.com/`。

实例子域是设计要求，因为 DSH Web 会从当前页面 origin 解析 API 调用。

## 3. 数据模型

service 持久化：

- namespaces；
- registry key 的 digest、prefix，以及当前可展示的 namespace 入伙凭证明文（如可用）；
- instances；
- instance token 的 digest 和 prefix；
- replacement grant 的 digest 和消费状态；
- idempotency records；
- audit events；
- health observations。

数据库可以持久化当前可展示的 registry key 明文，用于具备权限的 namespace 管理者展示/复制。replacement grant 和 instance token 签发后不得明文持久化；registry key 不得进入日志、审计 details、URL 或 tunnel 帧。

## 4. 安全模型

- 只有 trusted proxy 可以提供身份头。
- 认证/转发前会清理外部身份头。
- Portal 写操作要求 Origin + CSRF + 严格 schema 校验。
- Instance relay 同时要求中心认证/ACL 和一个在线授权 tunnel。
- DSH 接收经过清洗的 loopback-style 请求，因此 hub 是实际安全边界。
- Metrics 只供内部使用，必须避免 namespace/instance label 或 secret。

## 5. Registry key 与 instance token 语义

- 一个 namespace 同一时间只有一个 active registry key。
- 一个 registry key 可以注册多个 fresh installation。
- 轮换 registry key 只影响未来注册。
- 已有 instance token 在过期、轮换、leave 或 revoke 前保持有效。
- 已 revoke 的实例不得只用 registry key 自动重新注册。
- 恢复使用 owner 批准的短期 replacement grant。

## 6. Relay 设计

relay 使用 protocol v1.1：

- hello 和 capability negotiation；
- HTTP request/response frames；
- WebSocket open/data/close frames；
- cancel frames；
- 用于流控的 credit frames；
- heartbeat 和 health frames。

service 和 client/plugin 两端都会执行大小、超时和 backpressure 限制。

## 7. Plugin-first DSH 集成

plugin 路径提供：

- host-side DSH bundle；
- 复用 shared client tunnel runner 的 tunnel adapter；
- credential store；
- status view；
- diagnostics summary；
- browser settings card；
- same-origin status endpoint；
- 显式 remote capabilities overlay；
- `dsh-hub-web` 启动 helper；
- `plugin-install` 和 `plugin-join` CLI helper。

独立 agent 路径仍适合 diagnostics、bootstrap 和 fallback deployment。

## 8. 部署设计

公开部署示例是模板：

- `deploy/m2-local`：带 Caddy 和 Authelia 的 all-in-one local Compose。
- `deploy/m2-existing-caddy`：面向已有系统 Caddy 占用公网端口的后端 Compose 服务。
- `deploy/m3-observability`：metrics 和 alert rule validation。
- `deploy/m3-recovery`：本地 backup/restore rehearsal。
- `deploy/m3-logging`：log retention 和 redaction checks。

私有 production overlay 应位于公开仓库之外。

## 9. 兼容性说明

dsh-hub 跟踪特定 DSH seam：profile composition、plugin loading、browser client registration、web server routing、directory picker behavior，以及 DSH HTTP/WebSocket API。DSH 仍在演进，因此升级成为默认基线前应先通过隔离兼容矩阵验证。
