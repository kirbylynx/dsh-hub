# dsh-hub v0.1.4 release candidate

语言：[English](v0.1.4.md) | 简体中文

状态：release-candidate 文档。创建 `v0.1.4` tag 前，应先记录最终部署证据。

v0.1.4 聚焦自托管 operator 的生产发布卫生，不改变 tunnel protocol，也不扩大安全模型。

## 变更内容

- 新增公开生产就绪指南：
  - [生产就绪检查清单](../ops/production-checklist.zh.md)；
  - [发布运行手册](../ops/release-runbook.zh.md)；
  - [SQLite 备份与恢复指南](../ops/sqlite-backup-restore.zh.md)；
  - [existing-Caddy 共存指南](../ops/existing-caddy-coexistence.zh.md)。
- 明确 release candidate 与最终 tag 的流程区别。
- 明确真实部署证据、凭据、域名、IP 和 operator 路径应保存在公开仓库之外。
- 记录 Hub service、认证路由、hosted DSH、plugin tunnel 和 hosted model settings endpoint 的短时生产验收期望。

## 安全与运维说明

- `v0.1.4` 不新增 SaaS 多用户安全边界。
- `v0.1.4` 不新增真实 Alertmanager 接收人配置、生产长时压测、高可用或自动 hosted 实例分配。
- existing-Caddy 部署只有配置变化时才需要 validate Caddy/Authelia；纯代码部署不应无必要 reload Caddy。
- SQLite 备份应使用在线备份语义，并在升级前通过临时路径验证。

## 验证计划

Release candidate 应通过：

```bash
git diff --check
npm test
npm run deploy:m2:check
npm run deploy:m2:existing-caddy:check
npm run deploy:m3:alerts:check
npm run deploy:m3:recovery:check
npm run deploy:m3:logging:check
npm run deploy:g11:hosted-dsh:check
npm run test:g13:hosted-model-settings
```

自托管 operator 还应私有记录服务器证据，包括备份完整性、Compose 来源、服务健康、认证路由、instance 子域、hosted DSH 健康状态和脱敏模型设置摘要。

## 仍不纳入范围

多用户角色、管理员界面、Portal 侧模型管理、自动 hosted 实例分配、生产长时压测、真实告警接收人配置和真实回滚演练仍是后续工作。
