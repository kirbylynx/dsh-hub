# dsh-hub v0.1.1 closeout

Language: English | [简体中文](v0.1.1.zh.md)

v0.1.1 closes the first experimental hosted DSH container baseline. It is a
self-hosted/operator-run template for manually running one DSH instance in
Docker and connecting it to dsh-hub through the existing plugin tunnel.

## Included

- `deploy/hosted-dsh/` Docker Compose template for one manually managed hosted
  DSH instance.
- Fixed DSH runtime baseline: `@deepseek-ai/dsh@0.1.0-rc.7`.
- Per-instance bind mounts for DSH home, workspace, and logs.
- One-time join flow through registry key or replacement grant without storing
  those one-time secrets in Compose.
- Hosted-only `hosted-capabilities.patch.yml`.
- Hosted-only restricted directory picker rooted at container `/workspace`.
- Tests and checks for the hosted overlay, restricted picker behavior, and
  deployment template guardrails.

## Explicitly not included

- Hosted instance pool automation.
- User self-service provisioning.
- Multi-user ownership or hosted instance assignment.
- Hostile-tenant SaaS isolation.
- Remote model/provider settings configuration.
- Remote native `openPath` replacement.
- Any tunnel wire-protocol change.

## Known follow-up

DSH's native `Settings → Models` page may report that settings are unavailable
from a remote hosted browser. This is not treated as a v0.1.1 blocker because it
touches DSH durable settings, credentials, API keys, authorization, and audit.
It should be handled as a separate owner/admin-controlled model/provider
configuration feature.

## Verification

- `npm test`
- `npm run test:g11:hosted-picker`
- `npm run deploy:g11:hosted-dsh:check`

The public repository contains generic templates and local verification. Real
server addresses, deployment evidence, credentials, and operator handoff notes
belong in a private operations overlay.
