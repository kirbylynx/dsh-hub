# dsh-hub v0.1.7 发布说明

语言：[English](v0.1.7.md) | 简体中文

状态：已收口的 release 基线。真实部署证据应保留在 operator 自己的私有仓库或运维记录中，不进入公开仓库。

v0.1.7 收口 G15：为受信自托管部署新增基于 LLDAP 的密码管理。它建立在 v0.1.5 多用户基线和 v0.1.6 namespace/admin console 之上，让用户可以在 Portal 中修改自己的密码，system admin 可以重置其他用户的密码。

## 本版包含

- 用户自助修改密码：
  - active user 可以在 `Settings -> Password` 修改自己的密码；
  - Hub 会先通过 LLDAP 校验当前密码，再设置新密码；
  - 自助修改成功后返回配置的 logout URL，引导用户用新密码重新登录。
- System-admin 重置密码：
  - system admin 可以在 Users 详情页重置其他 Hub 用户的 LLDAP 密码；
  - 每次重置必须填写审计 reason；
  - admin reset 不能针对当前管理员自己。
- 统一密码策略：
  - 8 到 256 个字符；
  - 至少包含一个 ASCII 英文字母和一个数字；
  - 拒绝全空白密码；
  - 保留首尾空格，不自动裁剪。
- LLDAP 集成加固：
  - 配置的 LLDAP bind/admin 账号受到保护，不能通过 Hub UI/API 修改密码；
  - LLDAP 认证失败与 LLDAP 服务不可用被区分处理，服务异常不会被误报成旧密码错误。
- 幂等与审计安全：
  - 密码写操作要求 `Idempotency-Key`；
  - 幂等重放不会重复执行 LLDAP password modify；
  - 请求 fingerprint 使用稳定的服务端 password idempotency HMAC key，不再依赖当前 token pepper；
  - 幂等记录和审计 details 不保存密码明文或裸密码摘要。
- 部署模板：
  - Compose profile 新增 `PASSWORD_IDEMPOTENCY_KEY_FILE` secret；
  - README 补充该 secret 的生成和配置方式。

## 协议影响

v0.1.7 不新增 tunnel frame 类型，不改变 relay 语义。G15 是围绕既有 `proto: 1`、`minor: 1` relay 协议扩展的 HTTP/Portal 管理面能力。

## 本版不包含

- 邮件找回密码或忘记密码流程。
- 邮箱验证。
- MFA、验证码或管理员二次认证。
- 密码历史或强制下次登录改密。
- 通用 DSH settings 或 credentials bridge。
- 敌对租户 SaaS 级隔离。
- Team-owned namespace、namespace 归属转移/删除、批量管理操作或自动 hosted 实例池分配。
