# dsh-hub v0.1.3 收口

语言：[English](v0.1.3.md) | 简体中文

v0.1.3 收口第一版 hosted DSH 模型/provider 设置基线。它不改变既有 tunnel
wire protocol，而是在 DSH Web 的 dsh-hub plugin card 中增加一个 hosted-only
的窄面设置路径。

## 已完成内容

- 新增非秘密 `deploymentMode` 元数据，Portal 和 plugin 状态面可展示实例为
  `remote`、`hosted` 或 `unknown`。
- service 数据库新增 `deployment_mode` 持久化字段，并提供 v1 到 v2 schema
  迁移。
- hosted DSH composition 支持 `DSH_HUB_DEPLOYMENT_MODE=hosted`。
- 新增同源 plugin 模型设置端点：
  - `GET/HEAD/POST /plugins/dsh-hub-plugin/model-settings.json`
  - `POST /plugins/dsh-hub-plugin/model-settings/test.json`
- hosted 实例的 browser card 增加窄面 UI，覆盖：
  - DeepSeek 官方 provider；
  - OpenAI-compatible / 自定义 Base URL provider；
  - `openai-completions` 与 `openai-responses` 协议选择；
  - provider 模型 ID 和默认模型选择。
- API key 只写入 hosted DSH 本地 credential store，不写入 Hub service 数据库、
  Portal payload、status payload 或 diagnostics。
- 读取响应只暴露 `configured`、`managed` 等凭据状态，不返回 API key 值或 raw
  credential ref 名称。
- API key 输入框留空会保留已有凭据，包括既有 DeepSeek credential ref。

## 安全与兼容

`deploymentMode` 是可选元数据，不是授权 token。Hosted 模型设置必须通过本机
hosted eligibility 检查，包括显式 hosted mode、hosted marker、可写 hosted
workspace root、可写 DSH settings/credentials seam，以及预期模型 provider
namespace。

缺失或非法 `deploymentMode` 按未提供处理。注册和 tunnel hello 继续兼容旧
client，hello 中非法值不会清空此前记录的合法模式。

v0.1.3 不改变 tunnel frame。service、client 和 plugin 继续使用协议
`proto: 1`、`minor: 1`。

## 验证结果

本次收口已验证：

- `git diff --check main..HEAD`
- `npm run test:g13:hosted-model-settings`
- `npm run deploy:g11:hosted-dsh:check`
- `npm audit --omit=dev --audit-level=high`
- `npm test`

最终 review 也扫描了真实域名、服务器 IP、本地用户路径和疑似真实 secret。
public 示例保持通用；真实部署证据应保存在运维者自己的 private overlay。

## 不纳入本版本

v0.1.3 不包含多用户角色、Portal 侧模型管理、管理员界面、托管实例自动分配、
完整 DSH settings bridge、remote `openPath` 替代 UI、无头控制 API、P2P 或
多中心路由。

## 运维提示

从 v0.1.2 升级的部署应重新部署 Hub service 和 hosted DSH 容器镜像，确保
service schema、Portal 模式展示、plugin browser card 和 hosted entrypoint
均运行同一份 v0.1.3 代码。
