# dsh-hub v0.1.6 release notes

Language: English | [简体中文](v0.1.6.zh.md)

Status: closed release baseline. Operator-specific deployment evidence should
stay outside this public repository.

v0.1.6 closes G3: the first namespace/admin console baseline for trusted
self-hosted deployments. It builds on the v0.1.5 Authelia + LLDAP multi-user
foundation and makes namespace, registry-key, instance lifecycle, diagnostics,
and audit operations manageable from the Portal.

## Included

- User-owned namespace model:
  - namespaces are logical instance groups owned by a Hub user;
  - shared access is granted through namespace memberships;
  - the same owner cannot create two active namespaces with the same normalized
    name, while different owners may use the same display name.
- Namespace management APIs and Portal flows:
  - active users can create and edit their own namespaces;
  - system administrators can create namespaces for active users;
  - namespace list and details expose stable owner, membership, role, instance,
    and audit metadata without exposing secret digests.
- Registry-key management:
  - authorized namespace managers can reveal and copy the current namespace join
    credential;
  - namespace owners can update the current registry key for future joins;
  - registry-key updates do not affect already issued instance tokens.
- Instance management:
  - replacement grants for controlled instance rejoin;
  - revoke and recover actions;
  - role-aware diagnostics entry points;
  - deployment-mode display for remote vs. hosted instances.
- Common admin UI improvements:
  - lightweight left-navigation Portal sections;
  - reusable pagination component for list pages;
  - clearer action availability by role and object state.
- Audited management writes for namespace edits, registry-key reveal/update,
  replacement grants, instance revoke/recover, member/invite changes, and user
  status actions.

## Protocol impact

v0.1.6 does not add tunnel frame types and does not change relay semantics.
G3 is an HTTP/Portal management-plane expansion around the existing
`proto: 1`, `minor: 1` relay protocol.

## Not included

- Hostile-tenant SaaS isolation.
- Team-owned namespaces or team administrator roles.
- Namespace ownership transfer, deletion, archival, or cross-namespace instance
  migration.
- Bulk admin operations.
- Self-service password changes or administrator password reset.
- Portal-side hosted model/provider administration.
- Automatic hosted instance pool assignment.
- Production long-running load-test reports, real alert receivers, or real
  rollback drills.
