# dsh-hub v0.1.1 收口

语言：[English](v0.1.1.md) | 简体中文

v0.1.1 收口第一版实验性的 hosted DSH 容器基线。它是自托管/操作者运行的模板，用于在
Docker 中手工运行一个 DSH 实例，并通过既有 plugin tunnel 接入 dsh-hub。

## 已包含

- `deploy/hosted-dsh/`：单个手工管理 hosted DSH 实例的 Docker Compose 模板。
- 固定 DSH 运行基线：`@deepseek-ai/dsh@0.1.0-rc.7`。
- DSH home、workspace 和 logs 的每实例 bind mount。
- registry key 或 replacement grant 的一次性入伙流程，不把这些一次性 secret 写入
  Compose 长期配置。
- hosted 专用 `hosted-capabilities.patch.yml`。
- hosted 专用、根目录固定为容器 `/workspace` 的 restricted directory picker。
- hosted overlay、restricted picker 行为和部署模板 guardrail 的测试与检查。

## 明确不包含

- 托管实例池自动化。
- 用户自助开通实例。
- 多用户归属或 hosted 实例自动分配。
- 面向敌对租户的 SaaS 隔离。
- 远程模型/provider 设置配置。
- 远程 native `openPath` 替代能力。
- 任何 tunnel wire protocol 变更。

## 已知后续项

DSH 原生 `设置 → 模型` 页面在远程 hosted browser 中可能提示 settings 不可用。该问题
不作为 v0.1.1 阻断项，因为它涉及 DSH durable settings、credentials、API key、授权和
审计。后续应作为独立的 owner/admin 受控模型/provider 配置能力处理。

## 验证

- `npm test`
- `npm run test:g11:hosted-picker`
- `npm run deploy:g11:hosted-dsh:check`

公开仓库只包含通用模板和本地验证。真实服务器地址、部署证据、凭据和运维交接记录应保留
在私有运维 overlay 中。
