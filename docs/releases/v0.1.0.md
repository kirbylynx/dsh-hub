# dsh-hub v0.1.0

Language: English | [简体中文](v0.1.0.zh.md)

v0.1.0 is the first MVP baseline for dsh-hub. It is suitable for trusted
self-hosted evaluation and local deployment experiments.

## Highlights

- Plugin-first DSH remote access path.
- Standalone client as fallback and diagnostic tool.
- Namespace, registry key, instance token, replacement grant, rotate, leave, and
  revoke flows.
- Full-page instance subdomain access to original DSH Web UI.
- HTTP and WebSocket tunnel relay with bounded flow control.
- Portal security baseline: trusted proxy identity, Origin/CSRF checks, CSP,
  ACL, pagination, and field minimization.
- DSH plugin status card, local diagnostics summary, browser status endpoint,
  remote directory picker overlay, and `canOpenPath=false` gating.
- Docker Compose deployment templates for local and existing-Caddy environments.
- Metrics, alert rule checks, recovery rehearsal, and logging/redaction baseline.

## Not included

- Multi-user roles and namespace sharing.
- Admin console.
- Session history lazy loading for very large conversations.
- Production release/tag automation.
- Hosted DSH container pool.
- Headless automation API.
- High availability, multi-center, or P2P routing.
- Strong hostile-tenant SaaS isolation.

## Verification

Recommended public verification commands:

```bash
npm test
npm run deploy:m2:check
npm run deploy:m2:check:deep
npm run deploy:m2:existing-caddy:check
npm run deploy:m2:existing-caddy:check:deep
npm run deploy:m3:alerts:check
npm run deploy:m3:recovery:check
npm run deploy:m3:logging:check
```

Deep deployment checks require Docker.

## Public hygiene

This release note intentionally avoids real deployment domains, public IPs,
local absolute paths, credentials, and private operational evidence. Keep those
details in a private deployment overlay.
