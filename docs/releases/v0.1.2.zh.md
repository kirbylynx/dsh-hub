# dsh-hub v0.1.2 收口

语言：[English](v0.1.2.md) | 简体中文

v0.1.2 收口第一版有界大会话历史加载基线。它不改变既有 tunnel wire protocol，而是改进远程 DSH Web UI 路径：限制 history 请求规模，在实例侧瘦身响应，约束缓冲大小，并保持日志脱敏。

## 变更内容

- 增加实例侧 DSH `session.history` 和 `subagent.history` HTTP API 处理。
- 远程 history 请求默认下压到 `maxMessages=20`。
- DSH event-style history 响应离开实例前会被瘦身：删除已结算 `assistant/chunk`，同时为已渲染 assistant message 保留足够的首段 chunk 上下文。
- 增加独立的 raw 与 normalized history 响应限制。默认 raw history response cap 为 8 MiB；normalized response target 为 512 KiB，hard cap 为 1 MiB。
- 增加浏览器侧 remote-origin-gated history autoload：远程会话先显示最新消息，用户向上滚动时再加载更早历史。
- 增加 history 专用错误分类和重试提示，不记录 DSH payload 内容、本地路径、API key、registry key、replacement grant 或 instance token。

## 配置

默认值有意保守，操作者可按环境调优：

- `DSH_HUB_HISTORY_MAX_MESSAGES`
- `DSH_HUB_HISTORY_TARGET_BYTES`
- `DSH_HUB_HISTORY_HARD_BYTES`
- `DSH_HUB_HISTORY_MAX_RAW_BYTES`
- `DSH_HUB_HISTORY_NORMALIZER=off`
- `DSH_HUB_HISTORY_AUTOLOAD=off`

`DSH_HUB_HISTORY_MAX_RAW_BYTES` 同时受既有 relay HTTP body limit 约束，避免 history 响应绕过 tunnel 内存包络。

手工远程 dogfood 也确认：此前有问题的大型会话已经可以通过远程浏览器路径正常加载。真实部署域名、服务器地址、日志和私有证据有意不放入公开仓库。

## 仍不包含

v0.1.2 不新增多用户角色、管理员后台、hosted 模型/provider 配置、remote `openPath` 替代 UI、无头控制 API、用户级 DSH 会话隔离、托管实例自动分配、P2P 或多中心路由。

## 协议兼容

v0.1.2 不改变 tunnel wire frame。service、client、plugin 继续使用协议 `proto: 1` 和 `minor: 1`。
