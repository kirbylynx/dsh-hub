# dsh-hub v0.1.4 release closeout

Language: English | [简体中文](v0.1.4.zh.md)

Status: released. Operator-specific deployment evidence is intentionally kept
outside the public repository.

v0.1.4 focuses on production release hygiene for self-hosted operators. It does
not change the tunnel protocol or expand the security model.

## What changed

- Bumped the workspace package versions and runtime-reported client/plugin
  versions to `0.1.4`.
- Added public production readiness guidance:
  - [production checklist](../ops/production-checklist.md);
  - [release runbook](../ops/release-runbook.md);
  - [SQLite backup and restore guide](../ops/sqlite-backup-restore.md);
  - [existing-Caddy coexistence guide](../ops/existing-caddy-coexistence.md).
- Clarified release-candidate versus final tag flow.
- Clarified that real deployment evidence, credentials, domains, IP addresses,
  and operator paths belong outside the public repository.
- Documented short production verification expectations for the Hub service,
  authenticated routes, hosted DSH, plugin tunnel, and hosted model settings
  endpoint.

## Security and operations notes

- `v0.1.4` does not add a SaaS multi-user security boundary.
- `v0.1.4` does not add real Alertmanager receiver setup, long-running
  production load tests, high availability, or automatic hosted instance
  assignment.
- Existing-Caddy deployments should validate Caddy/Authelia only when config
  changes. Code-only deployments should not reload Caddy unnecessarily.
- SQLite backups should be created with online backup semantics and verified in
  a temporary path before upgrades.

## Verification

The v0.1.4 release branch passed the local verification matrix:


```bash
git diff --check
npm test
npm run deploy:m2:check
npm run deploy:m2:existing-caddy:check
npm run deploy:m3:alerts:check
npm run deploy:m3:recovery:check
npm run deploy:m3:logging:check
npm run deploy:g11:hosted-dsh:check
npm run test:g13:hosted-model-settings
```

The release candidate was also deployed to a self-hosted existing-Caddy setup
with a manually managed hosted DSH container. Public release notes omit the real
domains, IP addresses, server paths, backup filenames, and instance IDs; those
belong in the operator's private evidence log.

The private deployment evidence included:

- pre-deploy Compose source checks;
- SQLite online backup and temporary read-only restore verification;
- Hub service health and `dsh_hub_build_info{version="0.1.4"}`;
- public authentication boundary checks for the Portal and hosted instance
  routes;
- public `/metrics` non-exposure check;
- hosted DSH container health;
- hosted plugin version `0.1.4`;
- redacted hosted model settings endpoint smoke check.

## Still out of scope

Multi-user roles, the admin console, Portal-side model administration, automatic
hosted instance assignment, long-running production load tests, real alert
receiver setup, and real rollback drills remain future work.
